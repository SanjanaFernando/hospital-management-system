## Data Flow

### 1. **Fetching Data**

```
User opens Dashboard
        ↓
page.tsx mounts
        ↓
useEffect → fetchWards()
        ↓
api.ts → fetch('/api/wards')
        ↓
api/wards/route.ts → connectToDatabase()
        ↓
lib/mongodb.ts → MongoClient.connect()
        ↓
Azure Cosmos DB (MongoDB API) or MongoDB Atlas/Local → Returns data
        ↓
JSON response → React State
        ↓
Components render with data
```

### 2. **Creating New Patient**

```
User fills form & clicks "Add Patient"
        ↓
page.tsx → createPatient(data)
        ↓
api.ts → fetch('/api/patients', { method: 'POST' })
        ↓
api/patients/route.ts → db.collection('patients').insertOne()
        ↓
Azure Cosmos DB (MongoDB API) → Saves document & returns _id
        ↓
Success response
        ↓
Update UI / Refresh data
```

### 3. **Updating Patient (Discharge)**

```
User clicks "Discharge" button
        ↓
page.tsx → updatePatient(patientId, data)
        ↓
api.ts → fetch(`/api/patients/${id}`, { method: 'PUT' })
        ↓
api/patients/[id]/route.ts → db.collection('patients').updateOne()
        ↓
Azure Cosmos DB (MongoDB API) → Updates document
        ↓
Success response
        ↓
Update UI
```

## Database Schema

### **Wards Collection**

```typescript
{
  _id: String,           // "ward-0"
  name: String,          // "Ward A - General Medicine"
  totalBeds: Number,     // 25
  createdAt: Date,
  updatedAt: Date
}
```

### **Patients Collection**

```typescript
{
        _id: ObjectId,                    // Auto-generated by MongoDB-compatible server (Cosmos DB / MongoDB)
  wardId: String,                   // "ward-0"
  name: String,                     // "John Smith"
  age: Number,                      // 45
  ageGroup: String,                 // "Adult" | "Child" | "Elderly"
  disease: String,                  // "Hypertension"
  priority: String,                 // "Critical" | "Urgent" | "Non-urgent"
  status: String,                   // "admitted" | "queued"
  admissionTime: Date,              // 2024-02-14T10:30:00
  dischargeTime: Date | null,       // 2024-02-18T14:00:00 (if discharged)
  queueWaitTime: Number,            // 45 (minutes)
  specialRequirements: [String],    // ["Oxygen Support", "ICU"]
  createdAt: Date,
  updatedAt: Date
}
```
                                (used to connect to Azure Cosmos DB via MongoDB API)

### **Beds Collection**

```typescript
{
  _id: String,           // "0-5" (ward index - bed index)
  wardId: String,        // "ward-0"
  bedNumber: Number,     // 5
  status: String,        // "available" | "occupied" | "maintenance"
  patientId: String | null,  // Patient ID if occupied
  createdAt: Date,
  updatedAt: Date
}
```

## API Reference

### **Wards Endpoints**

```
GET /api/wards
Response: Ward[]

POST /api/wards
Body: { name, totalBeds }
Response: { insertedId }
```

### **Patients Endpoints**

```
GET /api/patients
Response: Patient[]

GET /api/patients?wardId=ward-0
Response: Patient[] (filtered by ward)

POST /api/patients
Body: { name, age, ageGroup, disease, priority, wardId, ... }
Response: { insertedId }

PUT /api/patients/{id}
Body: { status, dischargeTime, ... (partial update) }
Response: { modifiedCount }

DELETE /api/patients/{id}
Response: { deletedCount }
```

### **Beds Endpoints**

```
GET /api/beds
Response: Bed[]

GET /api/beds?wardId=ward-0
Response: Bed[] (filtered by ward)

POST /api/beds
Body: { wardId, bedNumber, status, patientId }
Response: { insertedId }
```

## Connection Pooling

**How it works:**

```javascript
// lib/mongodb.ts
const mongoConnection = {
  client: null,
  db: null,
};

export async function connectToDatabase() {
  if (mongoConnection.client && mongoConnection.db) {
    // Return existing connection
    return { client, db };
  }
  // Create new connection
  const client = new MongoClient(MONGODB_URI);
  await client.connect();
  mongoConnection.client = client;
  mongoConnection.db = db;
  return { client, db };
}
```

Benefits:

- ✅ Reuses connections
- ✅ Reduces connection overhead
- ✅ Better performance
- ✅ Handles concurrent requests

## Security Best Practices

### Development

- ✅ Use connection string in `.env.local`
- ✅ Add `.env.local` to `.gitignore`
- ✅ Whitelist all IPs (0.0.0.0) for dev only

### Production

- ✅ Use environment variables
- ✅ Restrict IP whitelist
- ✅ Enable authentication
- ✅ Use strong passwords
- ✅ Enable encryption in transit
- ✅ Backup regularly
- ✅ Use connection pooling
- ✅ Implement rate limiting
- ✅ Validate all inputs
